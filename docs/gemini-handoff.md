# Передача проекту LLM-AutoBench (Handoff: після Етапів 1–3 із 5)

## Мета проекту та контекст магістерської роботи
Проект виконується для магістерської дисертації **«Дослідження ефективності застосування великих мовних моделей для автоматизації відповідей на типові запити користувачів»**.
Архітектурно та методологічно система жорстко розділена на два контури:
- **АВТОМАТИЗАЦІЯ (робочий конвеєр сапорту):** запит користувача -> класифікація наміру й BM25-пошук знань (`retrieval.py`) -> побудова промпта за стратегією P1..P5 без витоку еталону (`prompt_builder.py`) -> генерація відповіді з JSON/текстовим контрактом -> рішення про автоматичну відповідь або ескалацію на оператора.
- **ДОСЛІДЖЕННЯ ЕФЕКТИВНОСТІ (науковий стенд):** серійні експерименти, сліпий незалежний LLM-суддя за версіонованою рубрикою (`rubric_v1.yaml`), непараметрична статистика та економічний аналіз для перевірки трьох гіпотез на даних із SQLite:
  - **H1:** найкраща модель залежить від предметної сфери (`fintech`, `ecommerce`, `it_helpdesk`, `telecom`).
  - **H2:** стратегія промпта (P1..P5) і режим контексту (`gold`, `retrieved`, `none`) впливають на результат не менше, ніж вибір моделі.
  - **H3:** для більшості типових запитів достатньо дешевої моделі без втрати безпеки ескалації (Recall / низький FN).

Виконано **Етапи 1, 2 та 3 із 5** (ядро конвеєра, реєстр провайдерів/моделей із планувальником запитів, надійність судді та чесна статистика). Попереду Етапи 4 та 5 (глибоке перероблення інтерфейсу, візуалізацій та фінальне оформлення). Дотримуйтесь правил: українська мова інтерфейсу без емодзі, довгих тире та нумерації «Рис. 3.1», коментарі в коді лише «чому».

## 1. Неочевидні інженерні рішення (в один рядок з причиною)
- **Вибір моделей і маршрутів перенесено з `.env` у таблицю `model_registry`:** у `.env` лишилися тільки ключі та URL, щоб зміни в UI не перезаписували секрети й зберігали історію виявлених моделей.
- **Захист in-memory кешем `_QUOTA_PAUSED_RUNS` у `database.py`:** `renumber_experiment_runs()` вызывається при кожному читанні списку запусків і без цього кешу скидав би статус `paused_quota` назад у `incomplete`.
- **Повторення судді з `max_output_tokens=4096` та `thinking_budget=64`:** моделі з внутрішнім «міркуванням» (Gemini 2.5/3, Qwen, DeepSeek) витрачали всі 1000–1500 токенів на роздуми й повертали порожній рядок (97 помилок у логах).
- **Агрегація повторів (`repeat_index`) всередині `query_code` перед статистикою:** псевдореплікація завищувала обсяг вибірки `n` у критеріях Вілкоксона та Фрідмана.
- **Двостороння сумісність ключів у `_calc_group_metrics` (`stats.*` + плоскі поля):** фронтенд очікував вкладений словник `m.stats.integral_efficiency_pct.ci95_low`, через відсутність якого раніше малювалися нульові інтервали `[83.5; 83.5]` та `ДІ: [0; 0]`.
- **Збереження `price_list_cost_usd` паралельно з `is_free_tier`:** дозволяє будувати економічний Парето-фронт (гіпотеза H3) навіть коли запити фізично йшли через безкоштовний тариф Google/Groq.
- **Фолбек HTTP 400 у `llm_runtime.py` при `json_mode=True` або `thinkingConfig`:** деякі OpenAI-сумісні та OpenRouter-ендпоїнти відхиляють `response_format` або параметри бюджету думок, тому запит автоматично повторюється без них.
- **Окрема серія `execution_mode='sandbox'` для Пісочниці й Арени:** інтерактивні запуски пишуться в ту саму таблицю `evaluation_results`, але ізольовані від вибірки серійних наукових прогонів.

## 2. Що не дороблено або зроблено спрощено
- **Наповнення датасету для сфер поза `fintech`:** у `fintech` є 60 запитів (по 12 на категорію), тоді як у `ecommerce`, `it_helpdesk`, `telecom` зараз по 16 запитів (відсутня категорія `navigational`), про що чесно попереджає `scripts/audit_dataset.py` (поріг для H1 становить `>= 30` на сферу).
- **UI блоків Етапу 3 в аналітиці:** діагностика рубрики (ефект стелі, розподіл оцінок), матриця кореляцій Спірмена та блок валідації судді на ручній розмітці додані в `index.html`/`app.js` у базовому табличному вигляді без повноцінної інтерактивної верстки (чекає Етапу 4).
- **Семантична схожість (`SS`):** обчислюється детерміновано через комбінацію символьних триграм і стелізованих токенів без важких векторних ембедингів, щоб прогони працювали швидко й автономно без GPU.
- **Кеш результатів судді (`_JUDGE_RESULT_CACHE`):** зберігається в оперативній пам'яті процесу Python на час роботи сервера, а не в окремій таблиці SQLite.

## 3. Місця, де немає 100% впевненості (що перевірити руками)
- **Передача `thinkingConfig` для різних версій моделей Gemini (`gemini-2.5-flash` vs `gemini-3.1-flash-lite`):** перевірити руками на реальному API-ключі запуск дооцінювання суддею (`Суддя` на картці серії) та переконатися в консолі логів, що немає масових фолбеків HTTP 400.
- **Експорт та імпорт CSV ручної валідації судді:** у вкладці аналітики натиснути `Експорт вибірки (CSV)`, заповнити колонки `human_relevance..human_policy_adherence` (числами 1..5) для 5–10 рядків у Excel/LibreOffice, імпортувати назад через `Імпорт розмітки (CSV)` і перевірити появу таблиці з каппою Коена та Спірменом (зокрема кодування UTF-8 BOM після збереження в Excel на Windows).
- **Відновлення серії зі статусу `paused_quota`:** перевірити кнопку продовження (`Дооцінити / Продовжити`) на серії, яка зупинилася через денну квоту RPD.
- **Перемикач «Враховувати самооцінювання» в аналітиці:** перевірити, що при його ввімкненні/вимкненні перераховуються середні бали рубрики на картках моделей.

## 4. Відомі баги та обхідні шляхи
- **Зависання старих серій у статусі `running` при аварійному перезапуску сервера під час генерації:** при старті або оновленні списку серій бекенд синхронізує `completed_items`, але якщо серія лишилася у `running` без активного фонового таска, використовуйте кнопку скасування або повторного дооцінювання.
- **Подвійний клік по кнопці дооцінювання суддею:** якщо швидко натиснути двічі, другий запит поверне HTTP 400 (`Оцінювання цієї серії вже виконується у фоновому режимі`), що безпечно обробляється повідомленням у лог.
- **Кирилиця у шляху профілю Windows (`C:\Users\Николай\...`) у виводі консолі PowerShell:** у логах pytest/uvicorn можливі символи заміщення `` у стандартному потоці виводу Windows-1251; сама БД SQLite та FastAPI працюють строго в UTF-8. Для чистого виводу в терміналі виконуйте `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`.

## 5. Як запустити застосунок і тести на цій машині
Використовується локальний інтерпретатор Python 3.14:
```powershell
# 1. Перехід у робочу директорію
cd C:\Projects\llm_proj

# 2. Запуск повного набору тестів (28 тестів: ядро, провайдери, планувальник, суддя, статистика)
& "$env:LOCALAPPDATA\Python\pythoncore-3.14-64\python.exe" -m pytest tests.py -v

# 3. Запуск аудиту еталонного датасету (перевірка покриття фактів та балансу сфер для H1)
& "$env:LOCALAPPDATA\Python\pythoncore-3.14-64\python.exe" scripts/audit_dataset.py

# 4. Запуск веб-сервера FastAPI (інтерфейс доступний на http://127.0.0.1:8000)
& "$env:LOCALAPPDATA\Python\pythoncore-3.14-64\python.exe" -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```
