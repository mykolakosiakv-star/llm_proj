# LLM-AutoBench

Програмний комплекс до магістерської роботи «Дослідження ефективності застосування великих мовних моделей для автоматизації відповідей на типові запити користувачів».

Програма має дві частини.

1. **Автоматизація.** Конвеєр «запит користувача → пошук у базі знань → відповідь моделі → рішення, чи потрібен оператор». Працює у вкладці «Помічник».
2. **Дослідження ефективності.** Серії експериментів, які вимірюють, наскільки добре цей конвеєр працює і скільки це коштує, а також перевірка гіпотез H1-H3 і симуляція каскадної маршрутизації.

Інтерфейс українською. Стек: Python, FastAPI, SQLite, один HTML-файл із модулями JavaScript, Tailwind і Chart.js (обидва збережені локально).

## Для кого

- **Керівник підтримки:** яку модель взяти, скільки це коштує, які ризики.
- **Інженер із впровадження:** метрики, налаштування моделей і промптів, власні моделі.
- **Студент і викладач:** відтворюваність, експорт, пояснення кожної метрики.

## Гіпотези

- **H1.** Найкраща модель залежить від предметної сфери.
- **H2.** Стратегія промпту і якість знайденого контексту впливають на результат не менше, ніж вибір моделі.
- **H3.** Для більшості типових запитів достатньо дешевої моделі без втрати безпеки.

Вердикти рахуються автоматично (вкладка «Результати») і за малої вибірки чесно показують «замало даних».

## Запуск

```powershell
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Далі відкрити http://127.0.0.1:8000. Ключі провайдерів задаються у вкладці «Моделі» (зберігаються у `.env`, у git не потрапляють). Без ключів працює локальна модель через Ollama.

Тести (без платних викликів API, працюють на тимчасовій базі):

```powershell
pytest tests.py
```

Аудит еталонних запитів: `python scripts/audit_dataset.py`.

## Як рахується якість

Відповідь модель повертає у єдиному форматі JSON: `{"answer", "escalate", "reason"}`. Для кожного заміру:

- **FC** (повнота фактів): частка обов'язкових фактів еталона, які є у відповіді;
- **SS** (лексична близькість): схожість відповіді з еталоном;
- **HR** (індикатор непідтверджених згадок): у відповіді є числа чи назви, яких немає в наданому контексті;
- **Q = 0,65·FC + 0,35·SS − 15·HR** (ваги і штраф в `config.py`, чутливість до них показана у «Результатах»);
- відповідність формату JSON рахується окремо і в Q не входить;
- **шлюз ескалації**: порівняння рішення моделі з очікуваним дає TP, FP, FN, TN, recall, precision; пропущена обов'язкова ескалація (FN) вважається критичною помилкою;
- відповідь без валідного JSON вважається переданою оператору;
- **LLM-суддя** (модель іншого сімейства, самооцінка заборонена) виставляє окрему оцінку за рубрикою, у Q вона не входить; узгодженість із людиною перевіряється ручною розміткою (експорт та імпорт CSV, каппа Коена, Спірмен).

## Умови контексту в експериментах

- `no_context`: модель без бази знань (базова лінія);
- `gold_context`: модель отримує еталонний фрагмент;
- `retrieved_context`: фрагменти знаходить BM25 (top-k).

Різниця між `gold_context` і `retrieved_context` показує, скільки якості втрачається через неідеальний пошук.

## Стилі

`app/static/tailwind.css` зібраний локально. Після появи нових класів у `index.html` або `js/*.js` його треба перезібрати (потрібен Node.js):

```powershell
cd scripts/tailwind
npm install --no-save tailwindcss@3.4.17
npx tailwindcss -c tailwind.config.js -i input.css -o ../../app/static/tailwind.css --minify
```
